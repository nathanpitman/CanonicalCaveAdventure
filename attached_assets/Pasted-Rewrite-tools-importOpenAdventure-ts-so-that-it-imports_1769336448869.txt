Rewrite tools/importOpenAdventure.ts so that it imports Open Adventure YAML canon “as is”.

B) Descriptions:
- Use the canonical long description text for each location.

- Do NOT append extra narrative.

C) Exits / travel:
- Import exits exactly as defined in YAML.
- Create a move Action for every exit direction found in YAML for that room.
- Action format:
  { id: `go_${dir}`, label: `GO ${DIR_UPPER}`, type: "move", to: targetRoomId }
- Support all direction tokens from YAML (n,s,e,w,ne,nw,se,sw,u,d,in,out,enter,exit,up,down, etc).

- Do NOT prune “non-NSEW” directions.
- If a travel rule is conditional/complex and you cannot express it in our simple Action model, still preserve basic connectivity by:
  - emitting the move action
  - but add a comment in generatedStory.ts (or console warning) indicating “complex travel rule not modeled”.

D) Items:
- Import item definitions from YAML as-is: id/name/description if available.
- For usable:
  - Only mark items usable if YAML clearly indicates a consumable effect that maps to our existing useEffect model.
  - Otherwise usable=false.
  - If you cannot infer canonical usability safely, default usable=false (do not invent effects).
- Item placements:
  - Place items in the exact canonical starting locations from YAML.
  - For each room, set scene.items = [itemIds...] for items that start there.
  - Generate itemDescriptions for each item present:
    itemDescriptions[itemId] = "You see <ItemName> here."
  - Generate TAKE actions for each present item:
    { id:`take_${itemId}`, label:`TAKE ${ITEMNAME_UPPER}`, type:"event", addsItem:itemId, removesAction:true }

E) descriptionWithoutItems:
- If YAML provides a base description separate from dynamic item text, use it.
- If not, set descriptionWithoutItems = description (no clever stripping).

F) Intro / Help:
- INTRO_MESSAGES should match canon tone (minimal, not chasm-fall remix).
- HELP_TEXT should list commands and mention directions supported.

START SCENE:
