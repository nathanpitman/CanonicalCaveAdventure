Replit AI Brief: “Ascent” Mobile Web Text Adventure (MVP)

Goal

Build a mobile-first web app (runs in iPhone Safari/Chrome) for a single-player text adventure called Ascent. The game is playable in-browser, touch-friendly, and saves progress locally on the device.

The player has fallen into a vertical mining chasm and must explore tunnels, manage light, and escape. The interface is a chat-like narrative feed with quick action buttons plus a text input for commands.

Tech & Constraints
	•	Use Node.js + Express for the server.
	•	Use vanilla HTML/CSS/JS (no React needed) OR minimal framework if you strongly prefer (but keep it simple).
	•	Must be mobile responsive and feel like a native mobile experience.
	•	No database required: use localStorage for save/load.
	•	Keep content and engine separated so I can add story nodes later.

Core UX

Single screen layout:
	1.	Header bar
	•	Title: “Ascent”
	•	Buttons: New, Save, Load, Help
	2.	Main scroll area
	•	A message log (like chat bubbles) showing:
	•	narration
	•	system messages (inventory changes, warnings)
	•	player actions
	3.	Bottom action area
	•	Quick action buttons for the current scene (e.g., LOOK, GO NORTH, TAKE LAMP)
	•	A command input (text field) + Send button
	•	On mobile, the input remains usable and doesn’t break layout when keyboard opens.

Game Loop
	•	Game starts with an intro narrative and the player at scene_id = "chasm_base".
	•	The UI always shows the latest scene description, then offers available actions.
	•	Player can:
	•	tap a quick action button, OR
	•	type a command (e.g., “look”, “inventory”, “go north”, “take lamp”).
	•	Engine parses the command, updates game state, appends log entries, and returns the next scene + actions.

Game State (must persist)

Represent game state as a single JSON object:

{
  sceneId: "chasm_base",
  inventory: [],
  flags: { foundLamp: false, mappedChasm: false },
  stats: { light: 100, turns: 0 },
  notes: [] // player notes they can add later (optional)
}

	•	Light decreases by 1 each turn (each player action). Certain actions decrease more.
	•	If light reaches 0: player can still play but receives warnings and some actions become risky (for MVP just show warnings; no death required yet).

Story Content Format

Create story data in a separate file such as /public/story.js or /src/story.js (your choice). Use a structure like:

const SCENES = {
  chasm_base: {
    title: "Base of the Chasm",
    description: "Cold air. Dust. The chasm rises into darkness above...",
    actions: [
      { id: "look", label: "LOOK", type: "command", command: "look" },
      { id: "take_lamp", label: "TAKE LAMP", type: "event" },
      { id: "go_tunnel", label: "GO EAST", type: "move", to: "east_tunnel" }
    ]
  },
  east_tunnel: { ... }
};

Required Scenes (minimum)

Implement at least 6 scenes so it feels like a real prototype:
	1.	chasm_base (lamp found here)
	2.	east_tunnel (narrow tunnel, drafts)
	3.	old_gear_room (rusty mining gear, dead end + item)
	4.	split_passage (two directions choice)
	5.	underground_stream (obstacle; requires choice)
	6.	exit_slope (ends MVP with “you found a way out”)

Items (minimum)
	•	lamp (not in starting inventory; can be taken at chasm base)
	•	fuel (found later; increases light by +30 when used)
	•	chalk (optional; can set a flag “marked_path”)

Commands to Support (MVP)

Support these commands with simple parsing (case-insensitive):
	•	help
	•	look
	•	inventory / inv
	•	take <item> (only when item is present in scene)
	•	use <item>
	•	go <direction> and shorthand north/south/east/west
	•	save, load, new

If the command is unknown, respond with a helpful message (and suggest help).

Engine Rules (simple but consistent)
	•	Every valid action increments turns and reduces light by 1.
	•	Moving scenes:
	•	update sceneId
	•	print the new scene description
	•	refresh quick actions
	•	Taking items:
	•	add to inventory
	•	set relevant flags
	•	remove the action/item from that scene for the rest of the run
	•	Using items:
	•	use fuel increases light (cap at 100)
	•	show a message confirming the effect
	•	Win condition:
	•	arriving at exit_slope prints a “You escape” ending and offers New Game.

Save/Load
	•	Save stores the game state + log to localStorage under key ascent_save_v1.
	•	Load restores it. If nothing exists, show message “No save found.”
	•	New resets to initial state and clears the log.

Accessibility / Polish
	•	Large tap targets for buttons.
	•	Keep the log readable with good spacing.
	•	Auto-scroll log to newest message.
	•	Don’t let the page bounce/scroll weirdly on iOS (use a fixed layout where possible).
	•	Works as a single page app served from Express.

File/Project Structure (suggested)
	•	server.js (Express server)
	•	/public/index.html
	•	/public/styles.css
	•	/public/app.js (UI + controller)
	•	/public/story.js (scenes + items + actions)
	•	Everything should run with npm start.

Deliverable

A runnable Replit project where:
	•	opening the webview shows the game UI,
	•	the player can complete a short playthrough to the exit,
	•	save/load works,
	•	the story is easy to extend by adding scenes/actions in story.js.
